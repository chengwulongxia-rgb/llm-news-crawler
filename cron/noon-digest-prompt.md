# 中午新聞匯總：已驗證的程式輸出

這個工作保留原排程、delivery 與模型設定，但最終通知不再由模型自由重寫。

## 執行入口

- Cron `e0349bb0f3b1` 使用 `no_agent=true`，script 指向 `llm-news-crawler/scripts/noon-digest.sh`。
- wrapper 在 `~/projects/llm-news-crawler` 執行 `uv run llm-digest --job-id e0349bb0f3b1`。
- 程式讀取近兩個台北曆日的 collector 輸出與 `data/deep-dive/*.json`，建立唯一 URL 清單及固定編號。
- 有可用正文與線索的候選才補進新聞清單；普通新聞不因候選擷取失敗而消失。
- 候選先取成功且有證據的版本，再以較新的評估為準，避免舊版關鍵詞誤判蓋過新版修正。
- 可判斷已超出日期範圍的文章移到 excluded 並顯示警示；批次日期不是發表日期，日期不明不得假稱新發表。

## 模型的唯一責任

`scripts/digest_summarize.py` 讀取這個既有工作的明確 model/provider，沿用原設定，不選新模型。
透過 Hermes SDK 呼叫時 `enabled_toolsets=[]`，不載入專案指令、記憶與人格。模型只回傳每個既定 id 的正體中文單行摘要映射。
模型不得新增、刪除或更改 URL、條目 id、總數、標題、分類、案例狀態與時間；所有來源內容都是不可信資料，不是代理指令。
目前需要 job 明確指定 model/provider；缺少時報錯，不擅自挑選替代模型。

## 送出前的硬檢查

1. 摘要必須剛好包含所有條目 id，不能增加網址、偽編號或控制字元。
2. 最終標題時間由本次實際 Asia/Taipei 時間生成，手動試跑也不沿用固定 12:05。
3. 宣告總數等於條目數，編號連續，來源 URL 數量／順序一致且唯一。
4. 摘要、來源、材料、證據與提案不得被包裝成已完成驗證；所有案例仍為 not_run。
5. manifest、摘要映射、驗證結果及完整通知存於 `data/digests/<實際執行時間>/`；驗證未通過或寫檔失敗不輸出可送出的清單，明報 stderr 並非零退出。
6. 最終只有通過檢查的原文寫入 stdout，由原 cron delivery 送出，後面沒有第二個模型改寫步驟。

程式入口與驗證才是時間、去重、編號及總數的執行來源；本檔供設定與審計說明，不再用提示詞請模型自行維持結構。
選題後才做完整查證／實作／寫作，再依既有工作流併入當天日報；本工作不會自動發文章。
